PUBLIC DISCLOSURE POLICY

Show the capability—not the build instructions

This edition introduces the problem domain, engineering decisions and selected publishable evidence. Details required to reconstruct the system are intentionally excluded.

CURATED PUBLIC EDITIONNO SOURCE RELEASE

What is public?

  • Project problem statement and application domain.
  • Version evolution and the objectives of each generation.
  • Conceptual architecture and responsibility boundaries.
  • Financial principles, not formulas or parameters.
  • Selected historical output examples with evidence labels.
  • Actual qualification status and known limitations.

What remains private?

Intellectual property

Source code, proprietary algorithms, search logic, selection rules and implementation details.

Internal contracts

Schemas, field names, module contracts, storage layout and source tree maps.

Parameters

Thresholds, cadence, quotas, queue sizes, execution settings and exact policies.

Sensitive evidence

Raw logs, payloads, account data, identifiers, keys and complete private reports.

About copy prevention

A public website can discourage text selection, context menus and casual saving. It cannot reliably prevent Developer Tools, network inspection, OCR or screenshots. Therefore, the primary protection is not publishing reconstructive information—not claiming DRM.

GitHub Pages is not one-time access control.

Public content is observable. If information must remain private, it must not be placed in HTML, JavaScript, SVG or the history of a public repository.
